# Starlark Code Generation Guide

Read this before writing or modifying code that generates Starlark source
(BUILD files, `.bzl` modules, `defs.bzl`, etc.). Always use `starlark_utils`
for codegen — never string templates.

## Import

```starlark
load("@starlark_utils//starlark:starlark.bzl", Star = "starlark")
```

## Mental model

The API has three layers:

1. **Node builders** — `fn()`, `ref()`, `load_()`, `tstr()`, etc.
   return opaque dicts that describe *what* to render.
2. **Statement-level builders** — `assign()`, `return_()`, `block()`,
   `if_()`, `for_()`, `def_()` return node dicts for control flow and
   function definitions. Fluent method chaining guides valid construction.
3. **Renderers** — `gen()` (single-line), `igen()` (indented), `auto()`
   (inline if it fits, else indented) turn node values into source strings.

`file()` is the exception — it returns a pre-rendered string directly.

## Generating Files

Every generated file uses `Star.file(*parts, header=_HEADER)`. Parts are
top-level statements (loads, assignments, rule calls) joined by blank lines.
Empty/falsy parts are filtered automatically.

```starlark
_HEADER = "Generated by my_module. DO NOT EDIT."

def _root_build():
    return Star.file(
        Star.package(default_visibility = ["//visibility:public"]),
        Star.exports_files(["all.bzl"]),
        header = _HEADER,
    )
```

### Convenience helpers

These return pre-rendered strings (not node values) for common BUILD
boilerplate. Use them directly as `Star.file()` parts:

- `Star.package(**kwargs)` — `package()` call (via `auto`)
- `Star.alias(name, actual)` — `alias()` call (via `auto`)
- `Star.exports_files(files)` — `exports_files()` call (via `auto`)
- `Star.bzl_library(**kwargs)` — `bzl_library()` call (via `igen`)

### The render-helper pattern

The standard architecture is: define a small helper per generated file type,
each returning `Star.file(...)`. Call them from the repository rule impl.

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
```starlark
def _option_set_build(option_set, deps):
    return Star.file(
        Star.load_("@bazel_skylib//:bzl_library.bzl", "bzl_library"),
        Star.package(default_visibility = ["//visibility:public"]),
        Star.exports_files(["defs.bzl"]),
        Star.bzl_library(name = "defs", srcs = ["defs.bzl"], deps = deps),
        Star.alias(name = option_set, actual = ":defs"),
        header = _HEADER,
    )

# Called from the repo rule:
rctx.file("%s/BUILD.bazel" % option_set, _option_set_build(option_set, [dep]))
```
<!-- markdownlint-restore -->

## `Star.ref()` — bare identifiers

The single most important pattern. `ref(name)` emits an unquoted identifier
while everything else stays quoted by default:

```starlark
# In a struct — renders as DEFAULT, not "DEFAULT"
CFG = Star.igen(struct(
    name = "tools",
    default = Star.ref("DEFAULT"),
    configs = Star.ref("_CONFIGS"),
))

# In an assign — value renders as _CONFIG, not "_CONFIG"
Star.gen(Star.block(
    Star.assign("CONFIG", Star.ref("_CONFIG")),
    Star.assign("VERSIONS", Star.ref("_VERSIONS")),
))

# In a fn call
Star.fn("cfg.new", name = name, versions = Star.ref("VERSIONS_%d" % i))
```

Never use `quote_strings = False` to achieve this — use `ref()`.

## Bracket merging

When rendering indented (`igen`/`auto`), a `fn()` call whose only positional
argument is a container (`list`, `dict`, `struct`, `depset`) and has no kwargs
auto-merges the outer call brackets with the inner container brackets:

```starlark
# Without merging (two positional args — brackets stay separate):
Star.igen(Star.fn("depset", [1, 2], transitive = Star.ref("ts")))
# depset(
#     [1, 2],
#     transitive = ts,
# )

# With merging (single list arg, no kwargs):
Star.igen(Star.fn("depset", [1, 2]))
# depset([
#     1,
#     2,
# ])
```

This matches hand-written Starlark style for `depset([...])`, `struct(...)`,
and similar single-container wrappers. It only activates under `igen`/`auto` —
`gen` always renders inline.

## Load statements

`Star.load_()` returns a node fn call. Pre-render with `igen` when passing
as a `Star.file()` part:

```starlark
# Simple (inline rendering is fine for short loads)
Star.load_("@bazel_skylib//:bzl_library.bzl", "bzl_library")

# With renames — kwargs become `alias = "symbol"`
Star.igen(Star.load_(
    "@%s//%s:defs.bzl" % (repo, pkg),
    _CONFIG = "CONFIG",
    _VERSIONS = "VERSIONS",
))

# Collecting loads with computed aliases
load_args = {"_CFG_%d" % i: "CFG"}
loads.append(Star.load_("@%s//:defs.bzl" % repo, **load_args))
```

See `examples/bzl_modules.bzl` — `forwarding_stub` and `aggregator_module`
demonstrate load patterns end-to-end.

## Assignments

`Star.assign(target, value)` builds an assignment node. As a `Star.file()`
part, each gets auto-formatted with blank lines between. Group consecutive
assignments with `gen(block(...))` for adjacent lines:

```starlark
Star.gen(Star.block(
    Star.assign("VERSIONS", versions),
    Star.assign("DEFAULT_VERSION", default_version),
))
```

`gen()` keeps all values inline. Force multi-line for complex values
with `ref(igen(...))`:

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
```starlark
Star.gen(Star.block(
    Star.assign("DEFAULT", default_name),                    # inline
    Star.assign("_CONFIGS", Star.ref(Star.igen(tools))),     # multi-line
))
```
<!-- markdownlint-restore -->

For a single multi-line assignment: `Star.igen(Star.assign("CONFIGS", configs))`.

## Statement-level generation

Use statement builders to generate Starlark logic (control flow, function
definitions, assignments). Each builder returns a node dict that `gen()`
renders with correct indentation.

### Simple statements

```starlark
# Assignment
Star.assign("x", Star.fn("compute"))         # x = compute()

# Return
Star.return_(Star.expr("result"))             # return result
Star.return_()                                # return

# Block (sequence of statements)
Star.block(
    Star.assign("x", 1),
    Star.assign("y", 2),
)                                             # x = 1\ny = 2
```

### Fluent builders

Fluent chains use struct method chaining — autocomplete shows what's valid
at each step.

**`if_` / `elif_` / `else_`** — use `.done` when there is no else:

```starlark
# if/else
Star.if_(Star.expr("x > 0")).then(
    Star.fn("process", Star.expr("x")),
).else_(
    Star.fn("skip"),
)

# if without else
Star.if_(Star.expr("x > 0")).then(
    Star.fn("process", Star.expr("x")),
).done

# if/elif/else
Star.if_(Star.expr("x > 0")).then(
    Star.fn("handle_positive"),
).elif_(Star.expr("x == 0")).then(
    Star.fn("handle_zero"),
).else_(
    Star.fn("handle_negative"),
)
```

**`for_`** — `.do_()` terminates the chain:

```starlark
Star.for_(Star.expr("item"), Star.expr("items")).do_(
    Star.fn("process", Star.expr("item")),
)
```

**`def_`** — `.body_()` terminates the chain:

```starlark
Star.def_("_impl", "ctx").body_(
    Star.assign("out", Star.fn("ctx.actions.declare_file", "out.txt")),
    Star.return_(Star.fn("DefaultInfo", files = Star.fn("depset", [Star.expr("out")]))),
)
```

### Composing into files

Render statement constructs with `Star.gen()`, then pass the string to
`Star.file()`:

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
```starlark
impl_def = Star.gen(
    Star.def_("_impl", "ctx").body_(
        Star.assign("out", Star.fn("ctx.actions.declare_file", "out.txt")),
        Star.return_(Star.fn("DefaultInfo", files = Star.fn("depset", [Star.expr("out")]))),
    ),
)
rctx.file("impl.bzl", Star.file(impl_def, header = "Generated."))
```
<!-- markdownlint-restore -->

See `examples/starlark_logic.bzl` for progressively complex statement
generation examples.

## Concise API reference

### Renderers

| Function | Output |
| --- | --- |
| `gen(value, ...)` | Single-line |
| `igen(value, ...)` | Multi-line, indented |
| `auto(value, max_width=80, ...)` | Inline if fits, else indented |

### File composition

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
| Function | Returns |
| --- | --- |
| `file(*parts, header=None)` | Pre-rendered string (parts joined by blank lines) |
<!-- markdownlint-restore -->

### Node builders

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
| Function | Renders as |
| --- | --- |
| `fn(name, *args, **kwargs)` | `name(args, key=value)` |
| `load_(label, *args, **kwargs)` | `load("label", "sym", alias="sym")` |
| `expr(text)` / `ref(text)` | Bare unquoted text |
| `comment(text, remove_prefix=True)` | `# text` (one `#` per line, body dedented) |
| `tstr(text)` / `docstring(text)` | `"""text"""` (escaped) |
| `rstr(text)` | `r"text"` (no `"`, no newlines, no trailing `\`) |
| `rtstr(text)` | `r"""text"""` (no `"""`, no trailing `"` or `\`) |
| `glob(...)` / `select(...)` | `glob(...)` / `select(...)` calls |
| `binop(op, *operands)` | `a op b op c` (variadic, no auto-parens) |
| `listcomp(expr, target, iter, cond=None)` | `[expr for target in iter if cond]` |
| `dictcomp(key, val, target, iter, cond=None)` | `{key: val for target in iter}` |
| `ternary(cond, then, else_)` | `then if cond else else_` |
<!-- markdownlint-restore -->

### Statement builders

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
| Function | Renders as |
| --- | --- |
| `assign(target, value)` | `target = value` |
| `return_(value=None)` | `return value` or `return` |
| `block(*stmts)` | Statements on consecutive lines |
| `if_(cond).then(*stmts).else_(*stmts)` | `if cond:` block with optional else |
| `if_(cond).then(*stmts).done` | `if cond:` block without else |
| `if_(...).elif_(cond).then(*stmts)...` | Chained elif blocks |
| `for_(target, iter_).do_(*stmts)` | `for target in iter_:` block |
| `def_(name, *params).body_(*stmts)` | `def name(params):` block |
<!-- markdownlint-restore -->

### Convenience helpers (return pre-rendered strings)

| Function | Renders via |
| --- | --- |
| `package(**kwargs)` | `auto` |
| `alias(name, actual)` | `auto` |
| `exports_files(files)` | `auto` |
| `bzl_library(**kwargs)` | `igen` |

## Style rules

- **Separate data from codegen calls.** Extract `fn()` / `load_()` args into
  a named dict, pass with `**kwargs`:

  ```starlark
  cfg_new_args = dict(name = name, versions = Star.ref("VERSIONS_%d" % i))
  cfgs[name] = [Star.fn("cfg.new", **cfg_new_args)]
  ```

- **Use `Star.ref()`** for bare identifiers. Never use `quote_strings = False`.
- **Use plain strings** for simple top-level expressions
  (`"EXTENSIONS = sorted(CFGS.keys())"`). Use `gen`/`igen`/`auto` for
  structured data (dicts, lists, fn calls).
- **Compose files** with `Star.file(*parts, header=...)`. Use `Star.docstring()`
  or a plain string for the header — `file()` wraps plain strings in `tstr()`
  automatically.

## Test expectations

Use triple-quoted strings that visually match the generated output.

- **`"""\` pattern** — when leading whitespace matters (indented output):

  ```starlark
  expected = """\
      FOO = 42
      BAR = "foobar"\
  """
  ```

  `"""\` avoids a leading newline; `\` before closing `"""` avoids a trailing
  one.

- **`'''` for output containing `"""`** — e.g. files with headers:

  ```starlark
  expected = '''\
  """Generated by my_module. DO NOT EDIT."""

  package(default_visibility = ["//visibility:public"])
  '''
  ```

- **`.strip()` is fine** when the output starts at column 0:

  ```starlark
  expected = """
  {
      "a": "foo",
  }
  """.strip()
  ```
