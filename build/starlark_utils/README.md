# `starlark_utils`

Bazel module for programmatically generating valid Starlark source code
(`BUILD` files, `.bzl` modules, etc.) from native Starlark values.

## 📦 Install

Make sure you are running Bazel with [Bzlmod]. Then, add the module as a
dependency in your `MODULE.bazel`:

```starlark
bazel_dep(name = "starlark_utils", version = "<VERSION>")
```

<details>
<summary><h3>Non-registry overrides</h3></summary>

If you need to use a specific commit or version tag from the repo instead of a
version from the registry, add a [non-registry override] in your `MODULE.bazel`
file, e.g. [`archive_override`]:

<!-- markdownlint-capture -->
<!-- markdownlint-disable MD013 -->
```starlark
REF = "v<VERSION>"  # NOTE: can be a repo tag or a commit hash

archive_override(
    module_name = "starlark_utils",
    integrity = "",  # TODO: copy the SRI hash that Bazel prints when fetching
    strip_prefix = "starlark_utils-%s" % REF.strip("v"),
    urls = ["https://github.com/jjmaestro/bazel_starlark_utils/archive/%s.tar.gz" % REF],
)
```
<!-- markdownlint-restore -->

**NOTE**:
`integrity` is intentionally empty so Bazel will warn and print the SRI hash of
the downloaded artifact. **Leaving it empty is a security risk**. Always verify
the contents of the downloaded artifact, copy the printed hash and update
`MODULE.bazel` accordingly.

</details>

## 🚀 Getting Started

Import the library:

```starlark
load("@starlark_utils//starlark:starlark.bzl", Star = "starlark")
```

### Generate a `BUILD` file

Define a render helper that returns a pre-rendered string:

```starlark
_HEADER = "Generated by my_module. DO NOT EDIT."

def _root_build(srcs):
    return Star.file(
        Star.package(default_visibility = ["//visibility:public"]),
        Star.exports_files(srcs),
        header = _HEADER,
    )
```

Call it from a repository rule impl:

```starlark
def _impl(rctx):
    rctx.file("BUILD.bazel", _root_build(["all.bzl"]))
```

### Generate a rule implementation

Use `Star.def_()`, `Star.if_()`, `Star.for_()`, `Star.assign()`, and
`Star.return_()` to build Starlark logic:

```starlark
def _rule_impl():
    return Star.gen(
        Star.def_("_impl", "ctx").body_(
            Star.assign("out", Star.fn("ctx.actions.declare_file", "out.txt")),
            Star.if_(Star.expr("ctx.attr.verbose")).then(
                Star.fn("print", "generating output"),
            ).done,
            Star.return_(Star.fn("DefaultInfo", files = Star.fn("depset", [Star.expr("out")]))),
        ),
    )
```

This produces:

```starlark
def _impl(ctx):
    out = ctx.actions.declare_file("out.txt")
    if ctx.attr.verbose:
        print("generating output")
    return DefaultInfo(files = depset([out]))
```

### Generate a `.bzl` module

Use `Star.assign()` with `Star.block()` and `Star.gen()` / `Star.igen()` for
values and `Star.ref()` for bare identifiers:

```starlark
def _all_bzl(versions, default_version):
    struct_dict = dict(
        name = "my_tool",
        default = Star.ref("DEFAULT_VERSION"),
    )
    return Star.file(
        Star.gen(Star.block(
            Star.assign("VERSIONS", versions),
            Star.assign("DEFAULT_VERSION", default_version),
            Star.assign("CFG", Star.ref(Star.igen(struct(**struct_dict)))),
            Star.assign("CFG_DICT", Star.ref(Star.igen(struct_dict))),
        )),
        header = _HEADER,
    )
```

This produces:

```starlark
"""Generated by my_module. DO NOT EDIT."""

VERSIONS = ["1.0", "2.0"]
DEFAULT_VERSION = "2.0"
CFG = struct(
    name = "my_tool",
    default = DEFAULT_VERSION,
)
CFG_DICT = {
    "name": "my_tool",
    "default": DEFAULT_VERSION,
}
```

## ✨ Features

- **Three-layer API**: node builders (`fn`, `ref`, `load_`, `tstr`, ...)
  and statement builders (`assign`, `if_`, `def_`, ...) describe *what* to
  render; renderers (`gen`, `igen`, `auto`) produce the source string. Compose
  freely without worrying about quoting or indentation.
- **Statement-level generation**: `assign`, `return_`, `block`, `if_`/`elif_`/
  `else_`, `for_`, `def_` — generate full Starlark logic, not just expressions.
- **Fluent builder API**: type-guided construction via struct method chaining.
  `Star.if_(cond).then(...).else_(...)` — autocomplete shows what's valid
  next.
- **`Star.file()` composition**: assemble generated files from parts (loads,
  assignments, rule calls). Empty parts are filtered, headers are auto-wrapped.
- **`Star.ref()` bare identifiers**: emit unquoted identifiers (`OPTIONS`, not
  `"OPTIONS"`) in any context: structs, assignments, fn calls, dicts.
- **Auto-rendering**: `Star.auto()` renders inline if under `max_width` (default
  80 chars), otherwise multi-line with indentation. Also manual control with
  `Star.gen()` and `Star.igen()`.
- **`BUILD` helpers**: `Star.package()`, `Star.alias()`, `Star.exports_files()`,
  `Star.bzl_library()` cover common `BUILD` boilerplate in one call.
- **Load statements**: `Star.load_()` with kwargs for symbol renames
  (`_CONFIG = "CONFIG"`). Pre-render with `Star.igen()` for multi-line output.
- **Expressions**: `glob()`, `select()`, list/dict comprehensions, ternary,
  binary ops, raw strings (`r"..."`, `r"""..."""`), and triple-quoted strings.
- **Stack-based renderer**: Starlark prohibits recursion, so the renderer uses
  an explicit stack to handle (almost) arbitrarily deep nested structures.
